# GBCast

Android shell for the Flycast core (Dreamcast, Naomi, Naomi 2 and Atomiswave) using the shared [GBFrame](https://github.com/mindspot7/GBFrame) library. The launcher is the GBCast game library. `NativeGLActivity` still renders with Flycast's existing GLES/Vulkan path.

GBFrame is the git submodule `libs/gbframe`; the repository records its required revision. The Android `applicationId` and Gradle `namespace` are both `app.gbcast.emulator`. `minSdk` is **28** because that is GBFrame's minimum; the previous Flycast Android app allowed API 21.

**Migration note:** changing the application ID from `com.flycast.emulator` to `app.gbcast.emulator` makes Android treat GBCast as a different app. Existing installations will not be updated in place, and app-private data will not automatically transfer. Back up any important data before switching.

## Android library

- Showcase, Grid and All in One come from GBFrame. Theme in the main menu switches them. The last selected game is restored by `LibraryView`.
- The games folder is a persisted Storage Access Framework tree. Indexed extensions: gdi, cdi, chd, cue, lst, zip, 7z, dat, bin. BIN/RAW/ISO tracks next to a GDI or CUE are not listed as separate games. GBCast first gives the core direct descriptor-backed paths; only CHD/ISO images are copied to a real cache file when a device cannot reopen that path. The library shows a blocking loading indicator while this fallback copy is prepared.
- Covers use libretro-thumbnails `Sega - Dreamcast` and are normalized by GBFrame to the system's majority box-art ratio; Dreamcast covers use a square `1.0` frame.
- **Cover Image** offers **Web Search** and **Local Search**. The in-app Google Images search previews a tapped/held image and applies it with **Use image**. Back returns through search history, the cover chooser, and game options to the library.
- **System > Dreamcast BIOS** imports `dc_boot.bin` (2048 KiB) and `dc_flash.bin` (128 KiB) together or separately, showing each file's installed/missing status. Invalid filenames or sizes do not replace existing firmware. Arcade BIOS/data files retain their separate importer.
- **Video > Display mode**, also available in the quick menu, is one exclusive choice: **4:3**, **16:9**, **Super widescreen** (expanded view at the device ratio), or **Fullscreen** (stretched picture). Changing modes clears incompatible aspect flags and resets legacy horizontal stretching. Built-in widescreen game hacks have one toggle in Video and default on for compatible games; Hardcore blocks them.
- **Cheats** includes 294 offline Dreamcast database files from libretro-database (CC BY-SA 4.0, attribution and license bundled). The shared database action adds supported native RAM operations without replacing manual cheats or compatibility patches; additions start disabled and duplicate imports are ignored. Matching is conservative about regions/revisions. Native `.cht` RAM imports and manual GameShark codes are supported; hardcore mode blocks changes. Supported 60 FPS patches are enabled by default and can be switched in the in-game **Performance** menu; Hardcore blocks their application.
- Overlay toggles (FPS, speed, CPU, GPU, renderer, resolution and frame time) live in **Settings > Video > Overlays** and **Quick menu > Overlays**. Automatic save/load remain in **Settings > System**; the quick menu does not duplicate these switches or the video Rotate switch.
- Game selection uses GBFrame's shared `HomeActions`: A/tap follows normal auto-load, Y/long press opens per-game options, Open starts without auto-loading a state, and Continue loads the selected state. The shared manual slot limit is five; quick/auto states are separate.
- GBFrame supplies the shared library layouts, main-menu icons and navigation, footer help bar, About page, and the standard Controls page (including remapping/hotkey capture with a Dreamcast-specific pad diagram). The in-game pause panel uses GBFrame's `QuickMenuHost`, with Flycast-backed save/load slots, video/audio/performance options, disc swap, restart, and per-game settings. The in-game Cheats entry uses GBFrame's shared `CheatsScreen` with a Flycast GameShark adapter. The shared GBFrame RetroAchievements settings and running-game achievements screen use the Flycast rcheevos client through a `RaBackend` adapter; HTTP is routed through GBFrame so casual-mode sessions can use its in-app offline cache, unlock queue, and reconnect synchronization. Hash lookup for library games that are not currently running is not exposed by the adapter yet.
- Frontends (ES-DE, Daijishou, Pegasus) and scripts can start a game through the library Activity with GBFrame's `LaunchIntent`: `am start -n app.gbcast.emulator/com.flycast.emulator.MainActivity -a android.intent.action.VIEW -d <content:// or file:// URI>` or `--es ROM "<path>"`. The game must be in the games folder (matched by file name), so multi-file discs, play time and auto load work as from the library. The legacy Flycast `VIEW` filter on `NativeGLActivity` still hands a URI straight to the core.
- Android Back during a game calls `gui_togglePause` and opens the quick menu. The system bars stay hidden (`BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`). A controller B press that is also reported as Back is not treated as the menu while gameplay is in front.

Build the APK from `shell/android-studio` (`assembleRelease` or `assembleDebug`). The single `Build GBCast` GitHub Actions workflow builds the ARM64 release APK after local validation. Unit/device tests, Android Lint and app-ID checks run locally; run `bash tools/check-app-id.sh` for the latter. See the [shared build and validation standard](libs/gbframe/docs/BUILD_VALIDATION_STANDARD.md). Device commands are available through `tools/gbcast.ps1` (requires `adb`; `Install` also requires authenticated `gh`). The release version is `shell/android-studio/VERSION` (versionName `<version> (build <versionCode>)`); a dispatch whose VERSION has no GitHub release yet publishes release `v<version>` with the matching `CHANGELOG.md` section. Releases are signed with the permanent GBCast key from the `GBCAST_KEYSTORE_BASE64` / `GBCAST_KEYSTORE_PASSWORD` secrets (alias `gbcast`); local release builds use it through `GBCAST_KEYSTORE_FILE` and `GBCAST_KEYSTORE_PASSWORD`, and fall back to the repository debug key without them.

The launcher and GBFrame's `HomeTopBar`, `HomeMenuPanel`, and `AboutPage` use the same GBCast foreground artwork (`R.drawable.ic_launcher_foreground` is the inline-compatible form), so the installed app, library, menu, and About page keep one identity. Development builds are named `GBCast-v<version>-build<versionCode>.apk`, and the Actions artifact uses the same stem. Numbered user releases should be named `GBCast-v<releaseVersion>.apk`, following the [GBFrame app integration standard](https://github.com/mindspot7/GBFrame/blob/main/docs/APP_INTEGRATION_STANDARD.md).

GBCast has no ads or analytics. Its optional network features and on-device data are described in the [privacy policy](PRIVACY.md).

# Flycast

The emulation core comes from [Flycast](https://github.com/flyinghead/flycast), a Sega Dreamcast, Naomi, Naomi 2, and Atomiswave emulator derived from [reicast](https://github.com/skmp/reicast-emulator). This repository keeps the Android shell and the core code that APK builds. Desktop, Apple, Switch, UWP, and libretro projects are not part of GBCast.

Configuration notes for the core are on [TheArcadeStriker's flycast wiki](https://github.com/TheArcadeStriker/flycast-wiki/wiki).
